**Animation note: **the sprite sheet (idle, walk, run, shoot, jump, hurt, sword attack) already exists as a one-off manual image-generation asset — a human gate per the GDD, not agent work. What’s still needed is turning that sheet into functioning in-engine animation: slicing frames into Paper2D flipbooks, and building the animation state machine (idle→walk→attack→hurt→dodge transitions) tied to controller inputs. # The One Rule for Using This Outline
 
Work top to bottom. If something later in the list seems more interesting or you get new information from class, resist jumping ahead or re-opening earlier phases without a concrete reason tied to something that actually broke — not just new ideas. Phase 0 is the clearest example: it took two sessions to lock, and re-litigating engine/agent-count decisions cost real time that could’ve gone into Phase 1.
